# Catalyst V1.1 Agents Foundation + Context Engineering Implementation Design

**Phase:** 3 — deterministic pre-Analyst harness <br>
**Date:** 2026-08-17 <br>
**Normative baseline:** `docs/plans/2026-08-16-catalyst-vnext-frozen-v1-design.md` <br>
**Factual baseline:** `docs/plans/2026-08-17-catalyst-v1.1-repo-reality-audit.md` <br>
**Data-layer baseline:** `docs/plans/2026-08-17-catalyst-v1.1-data-core-database-tsd.md`

This document defines the deterministic foundation immediately before the Evidence Analyst. It does not implement code, redesign downstream Analyst/Judge/Claim/Writer behavior, or replace the Frozen V1.1 architecture.

## 1. Executive Technical Assessment

The deterministic pre-Analyst harness is feasible, but not at equal depth on the current promoted data.

- The existing `ContextBuilder` already computes target return, volume ratio, benchmark/sector decomposition, peer median, deterministic quality flags, canonical serialization, and a persisted hash. It should evolve into the ObservationBuilder path, not be duplicated.
- The production `SQLiteContextProvider` currently reads only target OHLCV and explicitly returns no benchmark, sector, or peers. Direct inspection of the promoted snapshot finds 40 equity symbols but zero `SPY` rows and zero `XL*` sector ETF rows. The Phase-2 uncertainty is therefore resolved: current production data cannot compute market or sector context.
- The only relationship manifest edge is `AAPL → MSFT`, marked `fixture-review`; it is test evidence, not a production peer universe.
- Daily OHLCV contains `open`, `close`, and `volume`, so target return, prior-session return, gap return, and volume abnormality are implementable by evolving the current provider query.
- Macro observations are point-in-time capable (`92,680` rows, `12` series, all with `released_at`), but no production Observation reader or major-release mapping exists.
- Current Miner performs one generic retrieval call and flattens rich retrieval results into `retrieved_chunks`/`reranked_chunks`. It does not model typed research tasks, per-task failures, bounded concurrent task execution, or cumulative evidence state.
- Current Critic prompt packing is a hard `600`-character prefix per chunk. It is deterministic but not token-aware, section-aware, source-role-aware, or replay-complete.
- Existing trace infrastructure can persist all new run-scoped artifacts without a new database. `node_artifacts` is the correct store.
- The existing pinned BGE-M3 tokenizer provides deterministic tokenization and offsets, but it is an embedding tokenizer, not an exact tokenizer for every selectable LLM. Arbitrary OpenAI-compatible models require either a registered tokenizer or a conservative UTF-8-byte fallback.

Recommended architecture:

`ContextBuilder → evolved ObservationBuilder/MoveProfile → InitialResearchPolicy → bounded task executor → EvidenceState → CoverageSummary → ContextPackBuilder → EvidenceAnalystContextPack`.

The hard boundary is preserved: deterministic code reports observable data, retrieval, identity, eligibility, materiality, and coverage state; only the Evidence Analyst judges semantic relevance, causal support, contradiction, and missing evidence for a hypothesis.

- Frozen Pydantic models with `extra="forbid"`.
- Finite/positive guards and null-safe return formulas.
- Median-based volume denominator with a fixed expected window and minimum valid rows.
- Deterministic sorted peers.
- Canonical JSON bytes and SHA-256 artifact identity.
- Existing graph entry position before retrieval.

### Current limitations

- `SQLiteContextProvider` reads 21 target rows only; it does not select `open` or a third close needed for gap/prior-session return.

- `market_session_valid` is currently equated with `target_return_pct is not None`; session validity and price coverage are different facts.
- No scheduled macro lookup exists in the active context path.

### Alignment predicate

Given configured `flat_return_pct` and `aligned_residual_pct`:

```text
if target or reference missing/non-finite: UNKNOWN
else if abs(target) < flat_return_pct: TARGET_FLAT
else if abs(reference) < flat_return_pct: REFERENCE_FLAT
else if sign(target) != sign(reference): OPPOSITE_DIRECTION, DIVERGENT
else if abs(target - reference) <= aligned_residual_pct: SAME_DIRECTION, ALIGNED
else: SAME_DIRECTION, DIVERGENT
```

This intentionally avoids ungrounded correlation or beta estimates.

## 5. ObservationBuilder Design

`ContextBuilder` evolves into the ObservationBuilder implementation seam.

Data-core owns and returns a `StructuredObservationInputs` record containing:

- TemporalIdentity and exact regular-session dates;
- target open/close/volume and prior closes/volumes;
- mapped benchmark/sector identities and OHLCV when configured;
- effective point-in-time peer identities and OHLCV;
- macro release facts filtered by `released_at <= cutoff_at`;
- source/runtime identities and per-field data-quality flags.

Agents owns:

- return formulas;
- median peer aggregation;
- volume ratio/band;
- market/sector residuals;
- session-alignment classification;
- coverage/degraded interpretation;
- immutable MoveProfile construction and hash.

ObservationBuilder MUST NOT:

- query news or documentary evidence;
- infer a causal scenario from article availability;
- grade relevance or support;
- generate hypotheses;
- convert missing values to zero/false;
- fetch missing proxies implicitly.

Session validity is provided by TemporalIdentity/calendar validation. Price coverage is a separate `target_return_unavailable` degradation.

## 6. Scenario Classification

### Configuration

`ObservationPolicyConfig` is versioned and persisted in RunManifest:

```text
- material_target_return_pct
- material_prior_return_pct
- quiet_target_return_pct
- flat_reference_return_pct
- aligned_residual_pct
- volume_elevated_ratio
- volume_extreme_ratio
- minimum_peer_count
- require_sector_and_peer_for_broad_sector: true
- scenario_policy_version
```

Threshold values remain runtime/eval configuration, not architecture constants.

### Precedence and predicates

1. `SCHEDULED_MACRO`
   - at least one `ScheduledMacroFlag.importance == MAJOR`;
   - and `market_comove.band == ALIGNED` or `sector_comove.band == ALIGNED`;
   - unavailable market/sector alignment means predicate false with a coverage flag.
2. `CONTINUATION`
   - `abs(prior_session_return) >= material_prior_return_pct`;
   - `abs(target_return) >= material_target_return_pct`;
   - both returns have the same non-zero sign;
   - scheduled-macro predicate did not match.
3. `BROAD_SECTOR`
   - `abs(target_return) >= material_target_return_pct`;
   - `sector_comove.band == ALIGNED`;
   - `peer_comove.band == ALIGNED` and peer coverage meets `minimum_peer_count`;
   - no evidence/news input is consulted.
4. `COMPANY_SPECIFIC`
   - `abs(target_return) >= material_target_return_pct`;
   - at least one available market/sector/peer alignment is `DIVERGENT`;
   - absence of all comparators does not satisfy this predicate.
5. `QUIET_OR_UNCLASSIFIED`
   - `abs(target_return) < quiet_target_return_pct`; or
   - no stronger predicate matches; or
   - target return is unavailable.

Every classification emits `scenario`, `scenario_policy_version`, `matched_predicate`, `input_field_names`, and deterministic reason codes. It emits no confidence.

Current production will usually classify `CONTINUATION` or `QUIET_OR_UNCLASSIFIED`; it cannot honestly classify broad market/sector/company residual scenarios until Phase-2 structured context is expanded.

## 8. Initial Research Execution

Add one deterministic execution node between ObservationBuilder and EvidenceState construction. It reuses the existing `AgentRetrieverAdapter`/`ProductionHybridRetriever`; it does not create another retrieval engine.

```text
ResearchTaskResult
- task_id
- task_fingerprint
- priority
- status: SUCCEEDED | PARTIAL | DEGRADED | FAILED_CAPABILITY | FAILED_INTEGRITY
- started_at / ended_at / latency_ms
- deadline_exhausted
- evidence_items[] or structured_facts[]
- mode_requested / mode_served
- degradation_reasons[]
- error_code?
- data_runtime_identity
```

### Concurrency and deadline

- Execute independent tasks in `ThreadPoolExecutor` or equivalent bounded worker pool.
- `max_initial_research_concurrency` is runtime configuration and cannot exceed task count.
- All tasks receive one absolute monotonic stage deadline.
- Each task receives `remaining = stage_deadline - now`; it cannot reset the shared deadline.
- The current shared SQLite connection is not a safe task-level concurrency contract. The evolved data-core facade must use a read-only connection factory/pool per call while retaining the same retrieval implementation.

### Failure semantics

- Identity mismatch, invalid cutoff, invalid canonical IDs, manifest mismatch, or corrupt result schema → `FAILED_INTEGRITY` and fail the run.
- One backend timeout/unavailable arm with valid sibling results → `DEGRADED` task and continue.
- Unsupported evidence need → `FAILED_CAPABILITY`, continue, and emit deterministic capability gap.
- No eligible hits → successful empty result, not system failure.
- Shared deadline exhaustion → partial stage if at least one task is valid; otherwise retrieval-degraded abstention path, not fabricated evidence.

### Deterministic merge order

Raw task results are ordered by:

1. task priority ascending;
2. task ID ascending;
3. within-task final rank ascending;
4. evidence ID ascending.

EvidenceState then unions duplicate evidence IDs while preserving all task/modality contributions. Completion timing never affects order.

### Cumulative merge

`EvidenceState(t+1) = union_by_evidence_id(EvidenceState(t), NewEvidence)`.

- Same chunk from multiple tasks/modalities: one item, union contributions/task IDs.
- Same canonical article with multiple chunks: separate items sharing asset/content/document identity.
- Same chunk in two rounds: retain one item and original `first_seen_round`; append new contribution.
- Syndicated copies: separate canonical assets/items sharing one deterministic independence group.
- Same exact chunk with conflicting immutable identity/materiality metadata: integrity failure, not last-write-wins.
- Structured facts use stable `fact_id` union keys and remain separate from text items.

## 10. CoverageSummary Feasibility

CoverageSummary can remain fully deterministic if its names describe availability rather than semantic support.

The Frozen names `material_evidence_count` and `independent_report_count` are too easy to read as causal-support counts. Phase 3 requires a narrow terminology clarification, not an architecture change:

- `material_evidence_count` → `material_capable_asset_count` plus `material_capable_item_count`.
- `independent_report_count` → `eligible_reported_news_group_count`.
- `local_coverage_gaps` → split into deterministic `data_coverage_gaps` and `capability_gaps`.

CoverageSummary MUST NOT state that any item supports, contradicts, corroborates, or explains a hypothesis.

```text
- component
- reason_code
- requested_mode
- served_mode?
```

Semantic missing evidence for a hypothesis is absent from pre-Analyst CoverageSummary. It first appears in `AnalystDecision.proposed_missing_evidence` and normalized `EvidenceAssessment`.

### Algorithm

```text
validate EvidenceState identity, TemporalIdentity, and DataRuntimeIdentity

eligible_items = []
for item in evidence_items ordered by evidence_id:
    assert immutable identity fields are internally consistent
    if item.eligible_at > cutoff: continue
    eligible_items.append(item)

group eligible_items by canonical_asset_id
count content states, material-capable items, and material-capable assets
count distinct assets by deterministic evidence role

for each reported-news asset:
    if independence_status == KNOWN_GROUP:
        add asset to group[independence_group_id]
    else:
        increment unknown_independence_asset_count

derive eligible_reported_news_group_count from known groups only
derive duplicate/syndicated count from excess members in known groups
count parse-degraded items

aggregate task-result degradations by stable (task_id, component, reason_code)
copy deterministic data/capability gaps
copy MoveProfile alignment and scheduled-macro availability

return frozen CoverageSummary with canonical hash
```

No keyword matching, semantic contradiction detection, or model call occurs.

## 12. ContextPackBuilder Feasibility

ContextPackBuilder is feasible without an LLM because all required operations are deterministic over bounded run-scoped artifacts:

- hard identity/eligibility/materiality checks;
- retrieval rank and task-priority ordering;
- source-role partitioning;
- independence-group representative selection;
- section/chunk identity handling;
- tokenizer-aware excerpt boundaries;
- bounded inventory and payload allocation;
- explicit exclusions and truncation metadata.

It must not scan the corpus, retrieve new evidence, summarize text, infer contradictions, or create semantic relevance scores.

## 13. Ordering Algorithm

### Step 1: Validate and inventory

- Reject identity/runtime mismatch as a run integrity failure.
- Inventory every unique EvidenceState item.
- Exclude post-cutoff, `EMPTY`, and `FAILED` items from model context.
- `METADATA_ONLY` never contributes body text.
- `TITLE_ONLY` may contribute title metadata only and remains lead/existence-limited.

### Step 2: Compute deterministic utility key

For each item:

```text
best_task_priority = minimum contributing task priority
best_stage = RERANKER if reranker_rank exists
             else FUSION if fusion_rank exists
             else min(LEXICAL, DENSE) by available rank
best_rank = rank from best_stage
role_order = DIRECT_PRIMARY, PRIMARY_AUTHORITY, INDEPENDENT_REPORT,
             COMMENTARY_LEAD, STRUCTURED_CONTEXT, UNKNOWN
recency_key = eligible_at descending
tie = canonical_asset_id, corpus_document_id, section_key, chunk_ordinal, evidence_id
```

Primary sort is `(best_task_priority, best_stage_order, best_rank)`. Role, independence novelty, recency, and token efficiency are applied as staged selection constraints, not collapsed into a magical weighted score.

### Step 3: Novelty pass

Walk the relevance-ordered list and select at most one initial text representative per:

- canonical news asset;
- known news independence group;
- exact duplicate document group.

Filings are grouped by `(canonical_asset_id, section_key)`, not by whole filing, so distinct relevant sections survive.

### Step 4: Authority and payload pass

Within equal task/stage/rank bands, apply role order. Then prefer:

1. known non-degraded full text;
2. independence-group novelty;
3. later eligible timestamp within the task window;
4. lower token cost;
5. stable identity tie-break.

### Step 5: Additional filing chunks

After the novelty pass, admit additional retrieved chunks from a selected filing only when they have a distinct `(section_key, ordinal, content_hash)` and fit the remaining payload budget. No full-filing dump occurs.

## 14. Token Budgeting

### Token counter contract

```text
TokenCounter
- counter_id
- provider
- model_id
- tokenizer_id
- tokenizer_revision
- counting_mode: EXACT | REGISTERED_PROXY | UTF8_BYTE_UPPER_BOUND
- message_overhead_policy_version
- count_text(text)
- truncate_with_offsets(text, max_tokens)
```

Priority:

1. exact registered tokenizer for the selected model/provider;
2. explicitly approved conservative proxy tokenizer with recorded safety factor;
3. UTF-8 byte count plus configured per-message overhead as a fail-closed upper bound.

The existing pinned BGE-M3 tokenizer and `tokenize_with_offsets` are reusable for deterministic corpus-aligned counting/truncation, but must be labelled `REGISTERED_PROXY` unless the selected model uses that tokenizer. `characters / 4` is forbidden.

Arbitrary custom OpenAI-compatible models cannot claim exact counting without a registered tokenizer. They may run only under the conservative byte bound and a configured context limit, or be rejected for the Analyst role.

### Budget contract

All values are runtime configuration recorded in RunManifest:

```text
ContextBudget
- model_context_limit
- reserved_output_tokens
- reserved_system_instruction_tokens
- observation_tokens
- coverage_summary_tokens
- research_history_tokens
- inventory_tokens
- evidence_payload_tokens
- per_news_item_max_tokens
- per_sec_chunk_max_tokens
- lead_only_tokens
- safety_margin_tokens
```

Invariant:

`count(rendered_messages) + reserved_output_tokens + safety_margin_tokens <= model_context_limit`.

Packing fails closed before the model call if fixed metadata/instruction reservations alone exceed the limit.

## 15. Excerpt Selection

### News

- First version uses the repaired served chunk already returned by retrieval.
- No adjacent-chunk fetch and no semantic sentence window.
- Truncate from the start/end offsets supplied by the configured tokenizer only when the chunk exceeds the per-item cap.
- Preserve title, publisher, canonical URL, eligible time, asset/document/chunk IDs, and content hash.

### SEC

- Use repaired `filing_v3` successor chunks with accession, document, section key, ordinal, and parse quality.
- Pack retrieved section chunks; do not fetch or concatenate a full filing at request time.
- Additional same-section chunks are admitted only by the deterministic additional-filing pass.
- If section parsing is degraded, retain filing/document identity and degradation reason; do not label the excerpt as authoritative for a specific section.

### Official releases and other text

- Use their canonical served chunks under the same materiality and token rules.
- Structured macro/fundamental facts remain typed facts, not fake text retrieval chunks.

No semantic summarization or compression is introduced.

## 16. Duplicate Compression

### Syndicated or duplicate news

- One representative body per known independence group in the initial payload pass.
- Representative is chosen by the ordering algorithm: task relevance/rank, full-text/parse quality, role, recency, token cost, stable ID.
- Inventory preserves every member asset/evidence ID, provider, publisher, URL, eligible time, and representative ID.
- Group count remains one regardless of member count.
- Unknown lineage items are not collapsed as independent support; they remain individually inventoried and excluded from the known-group count.

### Filings

- Exact duplicate document/content hashes may collapse.
- Distinct sections of one filing never collapse solely because they share an asset/accession.
- Multiple chunks from one section remain eligible if distinct and relevant, subject to token budget.

### Chunk versus document dedup

- EvidenceState unions exact chunk identity.
- Context packing compresses document/group payloads.
- Neither operation deletes canonical evidence or task provenance.

## 24. Tests

All tests are deterministic and require no LLM.

### MoveProfile

- missing benchmark produces null market fields and `UNKNOWN` alignment;
- missing sector does not erase available market residual;
- partial peers produce `PARTIAL` coverage and stable median;
- after-close TemporalIdentity uses the correct session boundary;
- gap return uses session open/prior close;
- volume unavailable never becomes `NORMAL`;
- scenario precedence is stable under overlapping predicates;
- session validity is distinct from target-return availability.

### InitialResearchPolicy

- exact task set/order for every scenario;
- maximum three tasks;
- canonical task dedup and fingerprints;
- missing structured data falls to quiet/unclassified;
- no query/evidence/news field influences scenario;
- MARKET_STRUCTURE produces capability gap, not retrieval.

### EvidenceState

- lexical+dense duplicate chunk merges contributions;
- same chunk across tasks keeps all task IDs;
- same chunk across rounds keeps first-seen round;
- multiple chunks from one article remain separate;
- syndicated assets retain common group and separate IDs;
- immutable metadata conflict fails integrity validation.

### CoverageSummary

- material-capable item and asset counts differ correctly for multi-chunk filings;
- role counts are distinct-asset counts;
- known independence-group count excludes unknown lineage;
- metadata/title/full-text counts are exact;
- parse degradation is counted without changing materiality;
- retrieval degradation and data/capability gaps remain separate;
- no semantic support fields exist.

### ContextPack

- ordering is identical across task completion orders;
- rendered token invariant never exceeds budget;
- every included/excluded item remains inventoried;
- canonical asset/document/chunk identity survives;
- SEC section identity survives truncation;
- news duplicate compression chooses deterministic representative;
- distinct filing sections are not collapsed;
- round-two delta receives priority without deleting old evidence;
- canonical serialization/hash replay is byte-identical;
- exact counter, proxy counter, and UTF-8-byte fallback modes are labelled.

Answers to the final feasibility questions:

1. **CoverageSummary can remain deterministic.** It counts observable eligible items/assets, roles, content states, known independence groups, parse quality, structured availability, and retrieval degradation.
2. **Before the Analyst it knows availability, not support.** It cannot know whether evidence supports a cause, contradicts a hypothesis, or explains magnitude.
3. **ContextPackBuilder needs no LLM.** It uses hard gates, task priority, retrieval/reranker ranks, source roles, deterministic groups, timestamps, parse quality, token counts, and stable IDs.
4. **Its exact signals are available after Phase 2.** Current retrieval lacks several required fields, so production wiring waits for rebuilt contracts.
5. **Token-aware packing is practical for registered models.** Arbitrary custom models require conservative byte counting or rejection.
6. **SEC can be section-aware after repair.** Current 100% parse-degraded filing chunks are not sufficient for strong section provenance.
7. **End-to-end provenance can remain intact.** Phase-2 stable IDs plus persisted pack excerpts/offsets/hashes are sufficient.
8. **No core Frozen context-engineering requirement is unrealistic**, but exact arbitrary-model tokenization and semantic-sounding CoverageSummary names require narrow clarification.

## 31. Narrow Contract Clarifications

1. Interpret Frozen `material_evidence_count` as deterministic `material_capable_asset_count`/`material_capable_item_count`, not semantically supporting evidence.
2. Interpret Frozen `independent_report_count` as `eligible_reported_news_group_count`; semantic corroboration remains Analyst-owned.
3. Rename pre-Analyst `market_co_move`/`sector_co_move`/`peer_co_move` implementations to typed one-session `SessionAlignment`; they are not statistical correlations.
4. Split `local_coverage_gaps` into deterministic data coverage and backend capability gaps. Semantic missing evidence begins after Analyst output.
5. Exact token-budget guarantees apply only to registered tokenizers. Unknown custom models use a conservative UTF-8-byte upper bound or are ineligible for the Analyst role.
6. The current Frozen role arrays remain deterministic ContextPack views over one canonical payload list, avoiding duplicate mutable evidence representations.
