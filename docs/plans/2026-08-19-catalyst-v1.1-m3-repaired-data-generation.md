# M3 — Repaired Data Generation Accepted Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Produce and promote one versioned canonical DB/corpus/FTS/dense generation that is trustworthy and promotable, with a predeclared benchmark-accession SEC parse metric (DATA-01) and separated section-degradation reporting, without deleting any historical data.

**Architecture:** Build the repaired generation beside the current one; promote by pointer/version swap. Canonical identity (`canonical_assets` + content versions + associations) is the common registry; subtype tables (articles/filings) evolve; derived corpus/FTS/dense are rebuilt, never patched in place. Raw archives stay immutable.

**Tech Stack:** Python 3.11+, SQLite (WAL, connection-per-operation), existing corpus builders (`filing_v3`, `news_v2`, `streaming_publication`, `fts5_builder`), LanceDB import workflow (`build_index_from_artifacts.py`, `import_corpus_vectors_lancedb.py`), BGE-M3 GPU embedding (`build_corpus_embeddings_gpu.py`), existing SEC/news connectors.

**Normative authority:** Frozen V1.1 §5, §10 data gates. **Implementation authority:** Final Migration TSD §5.3, §27 M3, §29; Grok high-resolution DATA-01/DATA-02; Phase 1 TSD §15–21.
