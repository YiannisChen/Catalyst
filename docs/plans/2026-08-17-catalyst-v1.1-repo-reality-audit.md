### A.2 Actual graph path for a normal admitted run

The default graph is:

```text
context_builder
  → miner
  → critic
  → decision_router
      ├─ judge → validator → finalizer
      ├─ expand_macro → miner → ...
      ├─ insufficient_handler → finalizer
      └─ system_error_handler → finalizer
```

The edges and node registration are defined in `packages/agents/catalyst_agents/graph.py:build_attribution_graph`.

The actual normal execution is more specific than the graph declaration:

1. `context_builder_node` computes the canonical exchange cutoff through `ExchangeCutoffPolicy.compute_cutoff`, calls `ContextBuilder.build`, stores `context_artifact`, hashes it, and seeds `price_move_pct` and `market_session_valid` from `ContextBuilderArtifact.target_return_pct`. Evidence: `packages/agents/catalyst_agents/graph.py:context_builder_node`; `packages/agents/catalyst_agents/attribution/context_builder.py:ContextBuilder.build`.
2. `SQLiteContextProvider.load_context_inputs` reads at most 21 `ohlcv` rows for the requested symbol and session date, derives the previous close and prior volumes, and returns no benchmark ticker, sector ticker, or peer returns. Evidence: `packages/agents/catalyst_agents/runtime/context.py:SQLiteContextProvider.load_context_inputs`; SQLite table `ohlcv`.
3. `ContextBuilder.build` computes target return, volume ratio when at least 10 prior valid sessions exist, and optional market/sector/peer decomposition. In the production provider path, benchmark/sector/peer inputs are `None`/empty, so decomposition is unavailable and the artifact carries quality flags. Evidence: `packages/agents/catalyst_agents/attribution/context_builder.py:ContextBuilder.build`; `packages/agents/catalyst_agents/runtime/context.py:SQLiteContextProvider.load_context_inputs`.
4. `miner` builds either the user query or `Why did {ticker} move on {trade_date}?`, applies shared query ticker-claim policy, and fail-closes on a direct target mismatch before retrieval. Evidence: `packages/agents/catalyst_agents/nodes/miner.py:_build_query`, `miner`; `packages/data-core/catalyst_data/retrieval/query_policy.py:collect_query_claims`, `decide_claim_consistency`.
5. `miner` calls `catalyst_agents.retrieval.policy.retrieve`, which calls the injected `AgentRetrieverAdapter`. The production adapter calls `ProductionHybridRetriever.retrieve` with `candidate_depth=20` and `top_k=8`. Evidence: `packages/agents/catalyst_agents/retrieval/policy.py:retrieve`; `packages/agents/catalyst_agents/runtime/retrieval_adapter.py:AgentRetrieverAdapter.retrieve`; `packages/data-core/catalyst_data/retrieval/hybrid.py:ProductionHybridRetriever.retrieve`.
6. `ProductionHybridRetriever.retrieve` embeds the query, calls `retrieve_hybrid(mode="reranked")`, and returns at most eight final results. `retrieve_hybrid` attempts lexical FTS5 and dense LanceDB, fuses with reciprocal-rank fusion, and then applies the reranker when available; missing arms or reranker availability produce explicit degraded modes. Evidence: `packages/data-core/catalyst_data/retrieval/hybrid.py:ProductionHybridRetriever.retrieve`, `retrieve_hybrid`; `packages/data-core/catalyst_data/retrieval/fts5.py:retrieve_lexical`; `packages/data-core/catalyst_data/retrieval/dense.py:retrieve_dense`; `packages/data-core/catalyst_data/retrieval/reranker.py:RerankerGate`.
7. `miner` stores the adapter results as both `retrieved_chunks` and `reranked_chunks` after converting `RetrievalResult` objects. Because the adapter already returns `top_k=8`, the runtime state normally contains no separate 20-item candidate list even though state comments and artifact limits mention top-20. Evidence: `packages/agents/catalyst_agents/nodes/miner.py:miner`; `packages/data-core/catalyst_data/retrieval/hybrid.py:ProductionHybridRetriever.retrieve`; `packages/agents/catalyst_agents/trace/projection.py:_MAX_RETRIEVED`, `_MAX_RERANKED`.
8. `critic` returns immediately with a refusal decision when no chunks exist; otherwise it makes one LLM grading call through `invoke_with_retries`, applies temporal penalty/filtering, and returns `graded_evidence`, `all_graded_chunks`, and `CriticDecision`. Evidence: `packages/agents/catalyst_agents/nodes/critic.py:critic`, `_apply_temporal_penalty_and_filter`, `_build_critic_decision`; `packages/agents/catalyst_agents/backoff.py:invoke_with_retries`.
9. `decision_router` checks system error, ticker guard, market-session guard, magnitude guard, missing critic decision, and Critic next action. `proceed` goes to Judge only when `graded_evidence` is non-empty; `expand_related` is mapped to insufficient with `layer3_not_implemented`. Evidence: `packages/agents/catalyst_agents/nodes/decision_router.py:decision_router`, `route_after_decision_router`.
10. Current `critic.py:_build_critic_decision` emits `next_action="proceed"` for sufficient or partial evidence and `next_action="refuse"` for zero evidence; it does not emit `expand_macro`. Therefore `expand_macro` is graph-wired but not reachable from the current default Critic decision function without externally constructed state or future code. Evidence: `packages/agents/catalyst_agents/nodes/critic.py:_build_critic_decision`; `packages/agents/catalyst_agents/graph.py:expand_macro_transition`; `packages/agents/catalyst_agents/nodes/decision_router.py:decision_router`.
11. `judge` formats Critic-accepted evidence, makes one structured LLM synthesis call with up to five `HypothesisDraft` records, computes objective grounding rate from cited chunk IDs, and stores `judge_evidence`. Evidence: `packages/agents/catalyst_agents/nodes/judge.py:judge`, `_build_judge_evidence`, `_compute_grounding_rate`; `packages/agents/catalyst_agents/attribution/hypothesis.py:HypothesisDraft`.
12. `validator` either validates/enriches Judge drafts into `Hypothesis` records or requests one correction call when violations exist. It checks evidence IDs, cutoff, schema, and magnitude sanity, then produces status and validator artifacts. Evidence: `packages/agents/catalyst_agents/nodes/validator.py:validator`, `_enrich_drafts`, `_validation_failure`; `packages/agents/catalyst_agents/attribution/hypothesis.py:Hypothesis`.
13. `finalizer` ranks hypotheses and calls `determine_status` when hypotheses exist; otherwise it derives `SUFFICIENT`, `PARTIAL`, `ABSTAIN`, or `SYSTEM_ERROR` from current state. Evidence: `packages/agents/catalyst_agents/nodes/finalizer.py:finalizer`; `packages/agents/catalyst_agents/attribution/ranking.py:rank_hypotheses`; `packages/agents/catalyst_agents/attribution/output_status.py:determine_status`.

### C.3 FTS inventory and serving path

The promoted snapshot has both `corpus_chunks_fts` and `corpus_build_chunks_fts` schema objects; the content count observed is zero for `corpus_chunks_fts` and 591,012 for `corpus_build_chunks_fts`. The promoted `lexical_index_state` row for corpus manifest `327406...` has `mode_served="fts5"`, `lexical_generation_id=3839ca...`, and row count 295,506. Evidence: SQLite table `lexical_index_state`; `packages/data-core/catalyst_data/retrieval/fts5.py:_served_mode`, `_fts_from_clause`.

Because `lexical_generation_id` is present, `fts5._fts_from_clause` uses `corpus_build_chunks_fts` joined to the active served relation rather than the legacy `corpus_chunks_fts` branch. ### D.2 State contract and actual fields

`packages/agents/catalyst_agents/state.py:AttributionState` contains input fields, Miner retrieval fields, Critic grading fields, Judge causes/summary, status/validation fields, router/expansion fields, context/cutoff/manifest fields, hypothesis fields, cost/retry fields, and Arm-B/Arm-C evidence fields. The runtime runner seeds these fields in `packages/agents/catalyst_agents/runtime/runner.py:_load_state`.

Current state includes `critic_reasoning` and raw LLM response fields. `packages/agents/catalyst_agents/trace/projection.py:_STATE_COMPACT_KEYS` includes `critic_reasoning`, while raw response artifacts are truncated to 4,000 characters. This is an active reasoning-artifact surface, not merely a dormant comment.

### D.3 ContextBuilder

`packages/agents/catalyst_agents/attribution/context_builder.py:ContextBuilderArtifact` is versioned as schema `1.0.0` with formula revision `b5-context-v1`. It contains target close/return, previous close, target volume, prior-session volume statistics, benchmark/sector decomposition fields, peer returns, and data quality flags.

`packages/agents/catalyst_agents/runtime/context.py:SQLiteContextProvider` supplies OHLCV-only inputs and sets `benchmark_ticker=None`, `benchmark_return_pct=None`, `sector_ticker=None`, `sector_return_pct=None`, and `peer_returns_by_ticker={}`. Therefore the artifact schema has broader capability than the promoted production provider currently supplies.

### D.4 Miner/retrieval

`packages/agents/catalyst_agents/nodes/miner.py:miner` is the only default graph node that calls retrieval. It does not call providers directly. It delegates to `packages/agents/catalyst_agents/retrieval/policy.py:retrieve`, then to `AgentRetrieverAdapter`, then to `ProductionHybridRetriever`.

`packages/data-core/catalyst_data/retrieval/hybrid.py:retrieve_hybrid` attempts four conceptual arms in one call: lexical FTS5, dense LanceDB, hybrid RRF fusion, and reranked final results. The four-arm eval runner derives all four artifacts from one shared hybrid result; the default agent graph consumes only the final adapter results and does not expose separate arm outputs to the API.

### D.5 Critic

`packages/agents/catalyst_agents/nodes/critic.py:critic` is both an evidence grader and a sufficiency decision producer. It filters relevance at `RELEVANCE_THRESHOLD`, computes magnitude coverage, and returns `CriticDecision` with `sufficiency`, `next_action`, `magnitude_coverage`, and `reasoning`.

Current production behavior does not implement the frozen design’s separate raw AnalystDecision and normalized EvidenceAssessment boundary. The current `CriticResponse`/`CriticDecision` boundary is the implementation delta described by `docs/plans/2026-08-16-catalyst-vnext-frozen-v1-design.md:1410-1415`.

### D.6 Router and `expand_macro`

`packages/agents/catalyst_agents/nodes/decision_router.py:decision_router` has deterministic guards and edge selection. `packages/agents/catalyst_agents/graph.py:expand_macro_transition` loops to Miner with `Layer.MACRO`; `packages/agents/catalyst_agents/nodes/miner.py:miner` appends `macro market sector rates policy context` for that layer.

The graph has `max_expansions=2` in runner-seeded state and router logic, while `packages/agents/catalyst_agents/retrieval/policy.py` declares `MAX_EXPANSIONS=0` and `MAX_LAYERS_P0=1`. These are parallel/inconsistent policy constants. More importantly, current `critic._build_critic_decision` never chooses `expand_macro`, so the macro path is not verified on the default runtime.

### D.7 Judge, Validator, Finalizer

- `packages/agents/catalyst_agents/nodes/judge.py:judge` is one LLM synthesis node and produces up to five `HypothesisDraft` records, not a first-class claim plan.
- `packages/agents/catalyst_agents/nodes/validator.py:validator` is the current claim/evidence gate. It verifies evidence ID existence, `available_at`/cutoff, schema, prerequisite gates, magnitude threshold, and status; it can make one correction call.
- `packages/agents/catalyst_agents/nodes/finalizer.py:finalizer` ranks `Hypothesis` values and assigns terminal status, but it does not emit the frozen design’s explicit `ClaimPlan`, `ValidatedClaimPlan`, or `WriterInput` contracts.
