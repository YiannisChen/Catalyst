# M6 — Runtime / Event / Workbench Cut Over Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Durable `ACCEPTED` admission, bounded executor, atomic claim/events/artifacts, cooperative cancellation, race-safe SSE replay+live tail, Writer delta persistence, and an authoritative Workbench form one path — replacing daemon threads, polling, and the legacy live projection.

**Architecture:** App owns process-wide admission/executor and persistence transactions; agents owns only within-run research fan-out. SQLite is authoritative for run state/events/artifacts with `UNIQUE(run_id, seq)` and one-transaction publication; SSE replay reads committed rows and re-queries before every wait (SSE-01); Workbench consumes only public DTOs/events (API-01, AGENT-01 UI rules).

**Tech Stack:** Python 3.11+, FastAPI, SQLite (WAL, connection-per-operation), `ThreadPoolExecutor`, SSE (`text/event-stream`), Pydantic v2, React/Vite/TypeScript workbench, pytest, pytest-asyncio, Node built-in `node:test` for frontend. Do not introduce Vitest.

**Normative authority:** Frozen V1.1 §8–9. **Implementation authority:** Final Migration TSD §11, §15–21, §27 M6; Grok high-resolution SSE-01/RUNTIME-01; Phase 5 TSD §5–21.
