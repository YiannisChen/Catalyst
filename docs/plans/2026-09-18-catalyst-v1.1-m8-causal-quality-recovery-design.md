## 6. Text evidence and structured evidence stay separate

Do not dump everything into LanceDB. M3 already forbids structured facts in the
text vector store.

### 6.1 Text evidence: corpus / FTS / dense

- SEC filings and exhibits;
- issuer IR releases;
- government and regulator statements;
- cutoff-safe news **bodies** already available through approved sources;
- other public documents admitted by a predeclared, source-agnostic manifest.

Every citable text document carries source URL/type, source publication time,
ingestion time, cutoff eligibility, raw/body hash, document/chunk lineage,
content state, source class, ticker associations, and independence metadata.
`FULL_TEXT` without body/hash/lineage is rejected.

News is still Q-004: metadata-only rows cannot be promoted into fake bodies.
M8-A inventories retained news payloads, projects real bodies, and leaves
remaining metadata-only news as non-citable. Stage-1 news-needed cases pass
only if their underlying public documents are present through the **general**
source policy.

### 6.2 Structured evidence: EvidenceState, not vectors

- OHLCV and move profile;
- reported actuals and point-in-time consensus;
- sector/index/peer returns;
- macro observations;
- other certified point-in-time facts.

These stay in certified structured-fact tables and enter M4 EvidenceState.

### M8-A — production data recovery

Trace admitted documents through:

```text
raw/source -> canonical content version -> corpus build -> served relation
           -> FTS row -> dense row (when dense exists)
```

Classify: absent from source; present but not `FULL_TEXT`; canonical but
omitted from build; built but not served; served but not indexed; indexed but
not retrieved.

Then:

1. Seal source-selection inputs **before** any 19-ID membership audit.
2. Copy Q-001 into a **new** derivative; never write Q-001.
3. Rebuild with the repaired filing/news projection.
4. Import only generally declared source documents.
5. Stage inactive corpus + build-scoped FTS.
6. Leave active pointers unchanged.

Hard gates before any retrieval runner:

- production filing/official document counts match across raw → canonical →
  candidate chunks → candidate FTS;
- `FULL_TEXT` does not disappear in projection/build;
- candidate contains filing body chunks (current served generation has 0);
- post-seal 19-ID audit is 19/19 `FULL_TEXT`, cutoff-valid, candidate

## 9. Error handling and stop conditions

- Missing/mismatched source identity: stop before canonical projection.
- Benchmark/gold fields in source-selection manifest: reject the manifest.
- `FULL_TEXT` without body/hash/lineage: reject the document.
- Count/digest loss between canonical/build/FTS: stop before retrieval.
- M8-B failure: no provider, no GPU.
- M8-C failure: no GPU; inspect query routing, ranked evidence, ContextPack,
  then Analyst output, in that order. Do not loosen citation or materiality.
- Dense identity/count mismatch: no promotion.
- Mixed corpus/FTS/dense tuple: runtime inadmissible; rollback.
- M8-D hard-gate failure: publish an honest failed report; do not weaken
  thresholds; do not overwrite M7; do not start M8-E.

## 10. Test strategy

- FAST: manifest/schema validation, benchmark-isolation negatives, coverage
  state transitions, count/digest parity, metric calculations.
- MEDIUM: SQLite fixture from raw → canonical → candidate → FTS → candidate
  retrieval → ContextPack; no provider/GPU.
- EXPENSIVE-CPU: real derivative preparation, source-agnostic candidate build,
  M8-B retrieval, M8-C probe.
- EXPENSIVE-GPU: embedding, LanceDB staging, four-arm validation, atomic
  promotion, M8-D Stage-1 rerun.

Each package suite runs in a separate process with worktree-local
import-origin checks. Production DBs open `mode=ro&immutable=1` unless the
operator command explicitly targets the **new** derivative.

## 11. Rollback and retention

- Source code: revert focused M8 commits.
- DB: discard unpromoted derivative; never reverse-mutate Q-001.
- Corpus/FTS/dense: restore the prior recorded pointer tuple through the
  existing promotion journal.
- Eval: preserve every failed and successful run under distinct eval IDs.
- Data: raw archives and sealed M1–M7 artifacts are never deleted.

## 13. Path to WebGPT-level attribution (not M8)

M8 restores the intended **local corpus** path: when the public filing/IR/news
body is already in the served generation, Catalyst should retrieve it, pack it,
and let Analyst/Writer cite it instead of abstaining.

That is necessary and not sufficient for open-world research. Later:

- **M9 — bounded web-grounded causal research:** cutoff-safe fetch/cache/
  snapshot; official/news/IR routing; actual-versus-consensus; company/sector/
  macro query decomposition; competing hypotheses; contradiction and
  independence; bounded multi-hop. No always-on search. No free ReAct.
- **M10 — Stage-2 architecture validation:** 40–60 stratified human-reviewed
  cases; FTS/dense/hybrid/reranked comparison; A3/A4 retain/promote decision.
- **M11 — Stage-3 untouched holdout:** 15–20 cases; pre-registered metrics; no
  tuning. Required before any external quantitative efficacy claim.

web, a planner, or Stage-2 execution is out of scope.
