## M7 execution lock

### Canonical serialization and identities

All new M7 hashes use exactly:

```python
def canonical_bytes(value: object) -> bytes:
    return json.dumps(
        value,
        sort_keys=True,
        separators=(",", ":"),
        ensure_ascii=False,
        allow_nan=False,
    ).encode("utf-8")
```

The hash is lowercase `sha256(canonical_bytes(payload)).hexdigest()`.

- `case_list_sha256`: payload is the ordered JSON array of `case_id` strings. Never sort it.
- `dataset_content_sha256`: payload is the ordered array of `GoldenCase.model_dump(mode="json")` rows. README, filesystem path, whitespace, and the dataset manifest itself are excluded.
- `eligibility_hash`: payload is `{"experiment_id": experiment_id, "eligibility_predicate_version": eligibility_predicate_version, "ordered_eligible_ids": list(ordered_eligible_ids), "minimum_eligible_denominator": minimum_eligible_denominator}`. Never derive eligibility after outcomes exist.
- `eval_id`: hash the complete pre-execution identity payload: evaluation identity excluding `eval_id`, code/provider identity, data identity reference, retrieval policy, agent policy, metric contract, eligible experiments, and the empty planned run/artifact identity. Outcomes, timestamps, local paths, credentials, and observed run bindings are excluded.
- `run_manifest_hash` and artifact hashes are hashes of their existing authoritative canonical serialized bytes; M7 references them and never redefines their identities.

### EvalManifest lifecycle

The existing M2 `EvalManifest` remains the pre-execution immutable plan. For live runs its top-level `run_artifact_identity` is empty. M7 evolves `EvalOutcome` with `observed_run_artifact_identity: RunArtifactIdentity`, and evolves `CaseResultRef` with `run_manifest_hash`. No identity field is mutated after execution begins. Checkpoints are separate untracked execution-ledger artifacts; they are not rewritten as EvalManifest identity.

### Metric formula lock

- Aggregation is macro over eligible cases unless the metric explicitly names returned units/claims as its denominator; every aggregate carries integer numerator, denominator, eligible, excluded, and non-scorable counts plus case IDs.
- Recall@8 is `sum(relevant_unique_units_hit / relevant_unique_units) / eligible_cases`. MRR uses the first relevant unique unit rank. nDCG@8 uses gains `primary_support=3`, `secondary_support=2`, `contradiction=1`, all other roles `0`, binary temporal eligibility, and `log2(rank + 1)` discount.
- Primary-source hit is eligible cases containing at least one expected primary unit at rank <= 8 divided by cases with expected primary evidence.
- Duplicate-adjusted Precision@8 is acceptable unique human independence groups returned at rank <= 8 divided by all unique returned groups at rank <= 8. An ungrouped unit is its own group. Empty denominators are non-scorable, never zero or pass.
- Citation correctness, causal support, and unsupported-material decisions come only from the sealed human output-audit artifact. LLM judges remain diagnostics and cannot satisfy a hard gate.
- Percent thresholds are evaluated by integer cross multiplication; no rounded display value decides a gate.
