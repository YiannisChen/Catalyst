## 1. Why this amendment exists

### 1.1 Why commit `96f0009` was necessary after the first GPU run

The first GPU run of the M1 exit CLI surfaced AMEND-6: the Validator emitted every Judge draft into the published `hypotheses`/`causes` lists, including drafts whose prerequisite gates failed (e.g., critic-category-incompatible causes, `direction_mismatch`, missing OHLCV/peer context). Assurance then evaluated `prerequisite_gates` against the published set and could fail on a draft that should never have been published. `96f0009` fixed the emitted set: only gate-passed drafts are published, incompatible-only drafts correctly produce `ABSTAIN`. That commit is the correct baseline for publication of hypotheses/causes/status.

### 1.2 Residual P1: failed-gate causal content can survive in the public summary

`96f0009` filtered `hypotheses`/`causes` but returned the Judge's `summary_md` unchanged. When every draft fails prerequisite gates, the final state can still be:

- `output_status=ABSTAIN`, `hypotheses=[]`, `causes=[]`, but
- `summary_md` asserting the discarded causal hypothesis (and citing its evidence).

The same raw text is also persisted as the `("judge", "judge_summary")` node artifact before the Validator runs, and the workspace/API projection surfaces it as the public `summary_md`. So a failed-prerequisite causal assertion can survive in public/persisted fields even though the cause itself was dropped. This violates Frozen §3.2 ("Every material factual or causal claim MUST resolve to selected evidence from the same run") and the AGENT-01 lock (ABSTAIN output path must not render causal findings).

### 1.3 Why the existing tag/report are retained but superseded

`v1.1-m1-baseline` (annotated tag → `1da5314`) and `data/baseline/reports/v1_1_baseline_621375bc.json` are immutable historical artifacts. They record the first sealed GPU run, its NON-COMPARABLE verdict (Q-002 unrecovered), and its evidence bindings. Baseline tags and sealed reports are never deleted, rewritten, or retargeted (Master Plan §3.7/§3.10; M1 plan rollback rules). The corrective seal is a **supplemental** artifact: it supersedes the baseline for progression (M2 start) while preserving the original for audit.

### 1.4 Why fresh Git-bound GPU evidence is required after the fix

The residual leak is in production code (`packages/agents`). A report written from the pre-fix code cannot certify the corrected summary behavior. Evidence is bound to the executing HEAD: the operator CLI must run at the post-fix implementation HEAD, record `git_revision` equal to that HEAD, and bind fresh T4/four-arm/user-smoke evidence to that run. Historical `/workspace/catalyst-repo` evidence and the existing report are path-bound to earlier revisions and must not be reused or rewritten.

### 1.5 Q-002 status

Q-002 (promoted runtime env tuple) remains unrecovered. The corrected supplemental report stays explicitly **NON-COMPARABLE** (`promoted_env_recovered=false`, reason `q_002_promoted_environment_tuple_unrecovered`), exactly like the original. This corrective seal does not claim a comparable seal.

## 2. Confirmed defects and required invariants

### P1-A: failed-gate causal summary publication (agents)

Files: `packages/agents/catalyst_agents/nodes/validator.py`, `packages/agents/catalyst_agents/trace/projection.py`, `packages/agents/catalyst_agents/nodes/finalizer.py`, associated schema/API serialization paths and tests.

Invariants:

1. No failed-prerequisite hypothesis or causal assertion may survive in any public/persisted field, including `summary_md`/`judge_summary`.
2. When zero hypotheses remain publishable, output must use the repository's canonical non-causal ABSTAIN summary (deterministic, no causal assertion, consistent with the `insufficient_handler` convention).
3. When only some hypotheses remain publishable, the public summary must be derived only from the surviving hypotheses; it may not mention discarded hypotheses, their causal statements, or unsupported citations.
4. Frozen V1.1 status/output contracts are preserved; no new public schema.

Canonical convention used: `insufficient_handler` (`packages/agents/catalyst_agents/nodes/critic.py`) provides the repository's canonical non-causal ABSTAIN phrasing: a ticker/date-bound lead sentence plus the standard disclosure "This may indicate the price move was driven by factors outside our data coverage (private information, market microstructure, or sources we do not ingest)." The corrective gate-abstain summary follows that pattern without asserting any cause. The partial-publish summary is a deterministic Markdown list derived only from surviving hypotheses' `cause_label`, `transmission_mechanism`, and `supporting_evidence_ids`.

Implementation shape:

- Validator: after filtering to `published`, rebuild `summary_md` when `len(published) < len(hypotheses)` (or when the enrichment failed): canonical ABSTAIN summary when `published` is empty; surviving-hypothesis-derived summary when partial. Keep the LLM summary untouched when every draft is published (no filtering happened).
- Projection: `judge_causes`/`judge_summary` artifacts move from the Judge node to the Validator node so the persisted public artifacts are projected from the post-filter state (`causes` = published causes, `summary_md` = corrected summary). `judge_evidence`, `raw_llm_response`, `state_snapshot` stay at Judge (evidence fidelity/audit; raw LLM transcripts remain bounded audit artifacts redacted from baseline reports by the M1 adapter).
- Public workspace projection: prefer Validator-owned `judge_causes`/`judge_summary`, fall back to Judge-owned rows for legacy runs/fixtures. No WorkspaceResponse schema change.
- User-smoke required-artifact matrix: `judge_causes`/`judge_summary` become required under the `validator` node (same artifact types, same strictness, post-filter ownership). This is not a gate weakening; the artifacts are still required for every judge/validator path.

### P1-B: operator CLI lacks final provenance recheck (eval)

Files: `packages/eval/scripts/run_v1_1_m1_exit.py`, `packages/eval/catalyst_eval/baseline/report.py`, related tests.

Fail-closed behavior immediately before report publication:

- current HEAD still equals the expected execution HEAD;
- worktree still clean under the documented allowlist (M1 plan: empty `git status --porcelain` — no untracked/modified tracked files);
- frozen DB still has the expected SHA (`APPROVED_FROZEN_DB_SHA256`);
- gate/T4 evidence remains bound to this execution (recorded `evidence_meta_sha256`/`t4_meta_sha256` still match the on-disk files; run IDs still match the requested IDs);
- CLI success output and report `git_revision` cannot disagree (the writer enforces `expected_git_revision` before creating the final file).

A detected mismatch must prevent report creation (fail closed, no report file).
