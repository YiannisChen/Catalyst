## 1. Lock item A — Exact identity formulas

Every ID below is produced by builder functions in `packages/data-core/catalyst_data/canonical/ids.py`, which **M3-1 owns** together with `canonical_json_bytes` (the shared serializer below) and the stable ID builders for asset/content/document/fact IDs. M3-1 ships `test_canonical_ids.py` with **literal golden-vector tests**: exact `canonical_json_bytes` encoding, golden `asset_id`/`canonical_content_version_id`/`corpus_document_id`/`fact_id` values, non-finite (NaN/Inf) rejection, exact stored-PK sensitivity (no re-lowercase/reconstruction), and idempotency (same input → same ID on rerun). The builders evolve the existing primitives listed per item; no competing ID system is created.

**Shared canonical serialization (single locked definition; `canonical/ids.py` owns it):**

- Encoding (exact, locked):

```python
def canonical_json_bytes(value: object) -> bytes:
    return json.dumps(
        value,
        sort_keys=True,
        separators=(",", ":"),
        ensure_ascii=False,
        allow_nan=False,
    ).encode("utf-8")
```

then `hashlib.sha256(canonical_json_bytes(value)).hexdigest()` (lowercase, 64 hex). `allow_nan=False` is mandatory: NaN/Infinity can never enter an identity payload, matching the M2 contract's non-finite rejection rule for scores and JSON values (`canonical/model.py:_freeze_json`).
- Existing baseline serializers (`manifests/universe.py:canonical_json_bytes`, `corpus/streaming_publication.py:_canonical_bytes:374`, `corpus/manifest.py:compute_manifest_id`) currently omit `allow_nan=False`; they are **not** the V1.1 identity serializer. M3 code uses the locked definition above for every V1.1 identity payload. Baseline functions stay unchanged unless a task explicitly evolves them (A.6 evolves `streaming_publication._build_id`, which keeps its own `_canonical_bytes`).
- Null representation: **JSON `null`** for every optional/unknown input; keys are never omitted and never replaced with `""`. Empty string is reserved for genuinely empty text values (e.g., empty title), never for "unknown".
- UNKNOWN vs missing: both serialize as `null`. A builder never distinguishes them inside the hash payload; the projection layer records a typed reason column (e.g., `eligible_at_reason`) where the distinction matters.
- All normalization is applied **before** building the hash payload.

**A.1 `asset_id` (== `canonical_asset_id`; serialized field is exactly `asset_id`, no alias — M2 `canonical/model.py:CanonicalAsset.asset_id`, Final TSD §5.2).**

- Namespace/prefix: `v1:asset`. Final format: `v1:asset:{sha256_identity(payload)}` (prefix + 64 hex).
- Ordered input fields (dict keys sorted by canonical serialization; order in the list below is the semantic order, not the serialization order):
  - NEWS: `{"schema_version":"canonical_asset_id_v1","asset_type":"NEWS","source_table":"articles","source_pk":<exact stored articles.article_id as-is>}`. The exact stored subtype primary key is the identity input; `articles.article_id` is used verbatim (it is already `f"{provider}:{native_id}"`, `articles.py:82-84`, provider case preserved — **no re-lowercasing or reconstruction**).
  - FILING: `{"schema_version":"canonical_asset_id_v1","asset_type":"FILING","source_table":"filings","source_pk":<exact stored filings.filing_id as-is>}`. The exact stored subtype primary key is the identity input (no reconstruction from CIK/accession). One FILING asset per accession remains the backfill business rule (Final TSD §5.2); accession/CIK are carried in `subtype_metadata`, never reconstructed into the ID payload.
  - OFFICIAL_RELEASE / STRUCTURED_CONTEXT: **no text assets of these types are minted in M3**; structured facts are certified as `canonical_structured_fact_refs` rows, not as STRUCTURED_CONTEXT assets (§C).
- Normalization: `source_pk` uses the stored primary key verbatim — no case folding, no reconstruction, no trimming of the PK string. Ticker/CIK/accession normalization (ticker uppercase+strip; CIK zero-padded 10-digit; accession stripped, case preserved) applies only to `subtype_metadata`/ticker rows, never to the identity payload. `compute_article_id` does not lowercase the provider (`articles.py:82-84`), and the canonical payload must not lower it either.
- Collision: backfill fails closed if two subtype rows produce the same `asset_id` but differ in any projected field. Same identity payload from the same row is idempotent.
- Stability: `asset_id` never changes on corpus rebuild or content change (content change creates a new content version ID, never a new asset ID — Final TSD §5.2).
- Missing input (no article_id / no filing_id): row is **not** backfilled as a canonical asset; recorded in the audit `excluded_assets` count (fail closed, never synthesized).
- Legacy `storage/sqlite.py:compute_asset_id(ticker, date, source_type)` (`SHA-256("ticker|date|source_type|v1")`, `storage/sqlite.py:204-210`) is **unsuitable** for V1.1 canonical assets: it is ticker/date/source-type based, not subtype-identity based, and would break when content or corpus changes. It is **retained as legacy** for raw/clean asset addressing and is not used by the canonical backfill.

**A.2 `canonical_content_version_id`.**

- Namespace/prefix: `v1:content`. Final format: `v1:content:{sha256_identity(payload)}`.
- Payload (data-core TSD §12; **no `version_ordinal` in the hash**): `{"namespace":"v1:content","asset_id":..., "content_hash":..., "normalizer_version":..., "materiality_version":...}`.
- `content_hash` is **state-bound** so a changed content state can never collide with a different state's hash:
  - FULL_TEXT: `sha256(canonical_json_bytes({"content_state":"FULL_TEXT","normalized_body":<normalized body>}))`;
  - TITLE_ONLY: `sha256(canonical_json_bytes({"content_state":"TITLE_ONLY","normalized_title":<normalized title>}))`;
  - METADATA_ONLY: `sha256(canonical_json_bytes({"content_state":"METADATA_ONLY","normalized_title":<title or null>,"normalized_description":<description or null>,"canonical_url":<canonical_url or null>}))`;
  - EMPTY/FAILED: **mint no content version** (no `canonical_content_versions` row; `content_state` is recorded on the asset only).
  Normalized text uses the corpus normalizer `_normalize_text` (`corpus/news_v2.py:25-30`): NFC, `\r\n|\r → \n`, per-line `[ \t]+ → " "` with `rstrip`, blank-line runs collapsed to `\n\n`, final strip. Null fields serialize as JSON `null` (never omitted, never `""`), per the §1 null rule. The state label is a mandatory prefix input, not a separate column convention: identical normalized body bytes under different states produce different `content_hash` values.
- `normalizer_version`: per-subtype builder identity, e.g., `"sec_extract_v1"` (filing reparse parser version, M3-4) and `"news_body_v1"` (news body recovery version, M3-5). Any parser/body-recovery change bumps this string and therefore the content version.
- `materiality_version`: content-state classifier version only (e.g., `"materiality_v1"`). **`parse_quality` is a column/flag and never a hash input** — the same normalized body with a changed `section_parse_degraded` flag must keep the same content version ID.
- `version_ordinal`: 1-based **storage column** per asset (DDL `UNIQUE (asset_id, version_ordinal)`); a content change (new `content_hash` or new normalizer/materiality version) inserts ordinal+1. **Idempotency:** the same asset+content_hash+normalizer_version+materiality_version always yields the same `canonical_content_version_id` and reuses the existing version row; reruns never bump ordinals.
- Collision/duplicate: two version rows with the same version ID are merged (UNIQUE on `(asset_id, canonical_content_version_id)`); a same-version-ID row with a different `content_hash` is a hard failure.

**A.3 `corpus_document_id`.**

- Final format: 64 lowercase hex (must satisfy the existing `corpus/persisted_id.py:is_valid_persisted_document_id`).
- Payload: `{"corpus_document":"v1","content_version_id":..., "chunk_profile_version":...}` (data-core TSD §12: derived from content version and chunk profile version).
- Evolves: the corpus `document_id` field; current filing `document_id` values (v13) are already 64-hex and remain valid under the validator.

**A.4 `chunk_id`.**

- Final format: `{corpus_document_id}:{chunk_profile_version}:{section_key}:{ordinal}` — evolves the current grammar `{document_id}:{profile_version}:{section_key}:{ordinal}` (`corpus/news_v2.py:138`, `filing_v3.py`), with `document_id` replaced by the canonical `corpus_document_id`.
- `chunk_profile_version`: `"news_v2"` / `"filing_v3"` (unchanged constants) or their successors; `section_key`: normalized by `filing_v3._section_key` (lowercase alnum/underscore) or `"body"` for news; `ordinal`: zero-padded `ORDINAL_WIDTH=4`.
- The Final TSD §5.2 requirement that chunk identity be derived from content version, corpus document/profile, section, ordinal, and content hash is satisfied transitively: `corpus_document_id` is derived from `content_version_id`, which is derived from `content_hash`.
- Collision: fail closed on `UNIQUE (build_id, document_id, chunk_profile_version, section_key, ordinal)` (`corpus/streaming_publication.py:221`); identical input always yields identical `chunk_id`.

**A.5 `fact_id` (structured-fact certification; M3-2).**

- Namespace/prefix: `v1:fact`. Final format: `v1:fact:{sha256_identity(payload)}`.
- Payload (exact): `{"schema_version":"structured_fact_id_v1","fact_type":<fact_type>,"source_table":<source_table>,"natural_key":<natural_key>}` with `fact_type ∈ ('ohlcv','macro_observation','fundamental_statement')`, `source_table ∈ ('ohlcv','macro_observations','fundamental_statements')`, and `natural_key` = the **exact stored natural key** (mutable value/payload fields are excluded):
  - `ohlcv`: `{"symbol":<exact stored symbol>,"date":<exact stored date>}`;
  - `macro_observations`: `{"series_id":<exact stored series_id>,"observation_date":<exact stored observation_date>}`;
  - `fundamental_statements`: `{"statement_id":<exact stored statement_id>}`.
- `fact_id` rows are minted in M3 into `canonical_structured_fact_refs` (§B). Structured facts are **certified in M3 and consumed by M4**; they are NOT canonical text assets (`STRUCTURED_CONTEXT` text assets are not created) and are NOT stored in LanceDB. M2 `StructuredEvidenceIdentity` (`canonical/model.py`) remains the contract; structured `evidence_id == fact_id`.
- `source_pk_json` is **always** `canonical_json_bytes(natural_key).decode("utf-8")` — the locked shared serializer output (UTF-8, `sort_keys`, `(",",":")`, `allow_nan=False`), never a hand-written or alternate JSON spelling. Writer/audit tests reject: noncanonical alternate JSON spellings of the same natural key, duplicate semantic natural keys (same `(source_table, natural_key)` from different spellings), and `fact_id`/`source_pk_json` mismatches.
- `source_row_sha256` (separate from `fact_id`) binds the actual stored row under the snapshot: `sha256(canonical_json_bytes({"source_table":..., "source_pk_json":..., "row":{<column>:<value> for every column of the source row>}}))`, so a value change rebinds the row without changing the fact ID.

Output is 64 lowercase hex.

  3. `content_hash`

  13. `publisher`
  14. `canonical_url`

- Nested JSON rules (exact; **do not embed `canonical_json_bytes` output as a nested string/bytes value**):
  - `tickers` is a JSON array of strings, sorted lexicographically (`["AAPL","MSFT"]`), never a pre-serialized JSON string.
  - `subtype_metadata` is a JSON object/value matching the M2 `CanonicalAsset.subtype_metadata` thaw shape (object with unique keys). Duplicate keys, NaN, Infinity, and non-JSON types are rejected by `canonical_json_bytes(..., allow_nan=False)` / `_freeze_json`.
  - Other fields are JSON-native scalars (`str`, `int`, `bool`, or `null`). Datetimes enter as already-normalized UTC `Z` strings or `null`.
  - The complete 26-key row object is serialized **exactly once** with `canonical_json_bytes`. The resulting row bytes, followed by `b"\n"`, are fed to the digest hasher.

- Golden-vector tests (M3-1 `test_canonical_ids.py`) must lock: nested metadata, reordered object keys, reordered input tickers, null fields, and non-finite rejection.

## 2. Lock item B — Canonical schema ownership (v14 `canonical_registry`)

**content_hash ownership decision (single authority):** `canonical_content_versions.content_hash` is the **only stored authority** (Final TSD §5.2 "Normalized content hash is owned at the canonical content-version layer"). `canonical_assets` has **no stored `content_hash` column** (removed from the v14 DDL — no second writable copy). The M2 contract field `CanonicalAsset.content_hash: str | None` (`canonical/model.py:207`) is satisfied by **projection through the selected/latest content version** at read time: the serving-contract instance carries the hash of the asset's highest-`version_ordinal` content version, or `None` when the asset has no content version (EMPTY/FAILED). Dedup/content identity reads only `canonical_content_versions.content_hash`.

**v14 DDL** (applied by a new `Migration(version=14, name="canonical_registry", ...)` appended to `MIGRATIONS` in `packages/data-core/catalyst_data/migrations.py`, with the v13 savepoint/idempotency pattern; **never** added to `storage/sqlite.py` initial DDL):

## 4. Lock item D — Temporal and SEC rules

**Accepted-time source priority** (`sec/accepted_time.py`, M3-3; read-only sample verified):

1. EDGAR submissions JSON (`raw_assets.source_type='sec_filings'`): `recover_accepted_time(raw_payload, *, accession: str)` parses `recent.accessionNumber`, `recent.filingDate`, `recent.reportDate`, `recent.acceptanceDateTime` as parallel arrays; the accepted time for accession `A` is `recent.acceptanceDateTime[i]` where `recent.accessionNumber[i] == A` (index-aligned). The target accession must match exactly once and every parallel array consulted must have the same length; missing target, duplicate target, unequal arrays, or a malformed value at the target index fail closed. Verified present in 158/6,227 archived payloads; recovery is per-accession, not per-payload and never defaults to the first array element.
2. EDGAR index-headers HTML (`*-index-headers.html`/`.htm`): parse the `Accepted` field when the payload is retained in the archive (no such payloads currently retained; parser target locked for reimport).
3. Filing index HTML (`*-index.html`) and primary document headers: **do not** carry authoritative accepted time; used only as fallback evidence of `filed_at` date, never as accepted time.
4. `filings.filed_at`: date only; **never silently coerced to 16:00** (Final TSD §5.2; M3-3 negative test).

**Timestamp parsing / normalization (exact; SEC temporal parsing):**
- ISO-8601 inputs must contain `Z` or an explicit UTC offset. **A naive ISO datetime is rejected** (`fail_closed=1`, `eligible_at_reason='fail_closed_no_accepted_time'`); it is never passed to `normalize_utc_second_z` — the `timeutil.py:20,27-29` naive-as-UTC contract is **not** used for accepted-time recovery.
- EDGAR compact `YYYYMMDDHHMMSS` is interpreted in `America/New_York` (the SEC's publication timezone), then converted to UTC before storage; malformed or DST-ambiguous input fails closed.
- After parsing, normalize to UTC second-resolution `YYYY-MM-DDTHH:MM:SSZ` via `timeutil.normalize_utc_second_z` (aware input only). `TemporalIdentity` requires timezone-aware UTC (`canonical/temporal.py`).
- Date-only input (no time-of-day) is NOT parsed to a time; it is eligible only through `latest_plausible_instant` after Q-005 approval (§D).
- M3-3 required tests (exact): positive — `Z`-suffixed ISO, explicit-offset ISO converted to UTC, EDGAR compact interpreted as America/New_York→UTC (EST and EDT cases), multi-accession payload with the requested accession not first; negative — missing/duplicate target accession, unequal/malformed parallel arrays, naive ISO datetime, malformed string, DST-ambiguous instant, date-only input, and any naive datetime reaching `normalize_utc_second_z`.

**Accepted-time provenance:** recorded per asset (`accepted_time_recovered=1`, `temporal_precision='accepted_time'`, `eligible_at_reason='accepted_time_recovered'`) and per content version.

**Behavior when time-of-day is absent:** default **fail closed** (Final TSD §5.2): `eligible_at = NULL`, `temporal_precision='unknown_time_of_day'`, `fail_closed=1`, `eligible_at_reason='fail_closed_no_time_of_day'`. Under an operator-approved declared conservative rule (Q-005), `eligible_at = latest_plausible_instant(date)`. Fail-closed rows stay in SQL + audit and are never serving-contract instances (§C); a `NULL` `eligible_at` is the stored representation of not-eligible, never a sentinel timestamp.

**`derive_eligible_at` typed result** (`sec/eligible_at.py`): a frozen dataclass with exactly:

```python
@dataclass(frozen=True)
class EligibleAtResult:
    eligible_at: datetime | None          # None => not eligible
    eligible_at_reason: str               # vocabulary below
    temporal_precision: str               # vocabulary below
    accepted_time_recovered: bool
    fail_closed: bool
```

**`eligible_at_reason` vocabulary:** `accepted_time_recovered` | `publication_time_provider` | `ingestion_time_conservative` | `fail_closed_no_time_of_day` | `fail_closed_no_accepted_time` | `latest_plausible_approved` | `not_eligible`.

**`temporal_precision` vocabulary:** `accepted_time` | `publication_time` | `ingestion_time` | `date_only_latest_plausible` | `unknown_time_of_day` | `unknown`.

**Latest-plausible-instant fail-closed rule:** `latest_plausible_instant(d)` = `(d + 1 day) 00:00:00 America/New_York` converted to UTC — the instant at which date `d` ends in ET. This is the declared conservative rule (data-core TSD §7 "eligible only after the latest plausible instant consistent with the precision"). Example: Monday 2026-01-05 (EST, UTC-5) date-only → `latest_plausible_instant = 2026-01-06T05:00:00Z` (next-day 00:00 ET), which is after Monday's 16:00 ET close and before Tuesday's close → eligible for the Tuesday window, matching the M2 test `test_monday_1605_earnings_eligible_for_tuesday_window_via_calendar`. For an EDT date (e.g., 2026-05-01) the instant is next-day `04:00:00Z`. Rule requires operator approval before fail-closed rows count in DATA-01 numerator (Q-005).

**Weekend / holiday / premarket / after-close:** use `trading_calendar.py` (`is_trading_day`, `session_close_utc`, `calendar_trading_days`, `CALENDAR_YEARS` 2024–2027) and `retrieval/cutoff.py` `ExchangeCutoffPolicy`/`compute_cutoff`. After-close acceptance (e.g., Monday 16:05 ET) is eligible for the Tuesday window (`information_window_start_at = Monday close`, `cutoff_at = Tuesday close`). Friday after-close → Monday window (prior-session via calendar, never calendar-day subtraction).

**Q-005 operator approval:** required before any fail-closed row (`unknown_time_of_day` / `date_only_latest_plausible`) counts toward the DATA-01 numerator. Default is fail closed per Final TSD §5.2.

## 8. Lock item H — Audit formulas

`canonical/audit.py` (M3-7) computes the following exact predicates over the canonical tables. **One shared serving predicate is used verbatim in every ratio's numerator and denominator** (no divergent predicates):

```sql
-- shared serving predicate S
S = serving_status IN ('body_candidate','lead_candidate')
```

`serving_status` is derived at backfill time (exact mapping): `body_candidate` ⇔ `content_state='FULL_TEXT'` AND `eligible_at IS NOT NULL` AND `parse_quality != 'failed'`; `lead_candidate` ⇔ `content_state IN ('TITLE_ONLY','METADATA_ONLY')` AND `eligible_at IS NOT NULL`; `excluded` ⇔ `eligible_at IS NULL` OR `content_state IN ('EMPTY','FAILED')`. The audit additionally asserts derivation integrity (every `body_candidate`, `lead_candidate`, and `excluded` row satisfies its mapping above) as an invariant check, not as a second predicate.

| Gate | Exact predicate / formula (S as defined above) | Threshold |
|---|---|---|
| `searchable_news` | `COUNT(DISTINCT asset_id)` WHERE `asset_type='NEWS'` AND S | denominator |
| `searchable_serving_evidence` | `COUNT(DISTINCT asset_id)` WHERE S (all text-evidence asset types) | denominator |
| `source_class_present` | `COUNT(DISTINCT asset_id)` WHERE `asset_type='NEWS'` AND S AND `source_class IS NOT NULL AND trim(source_class) <> ''` | `source_class_present * 100 >= searchable_news * 95` |
| `publisher_present` | `COUNT(DISTINCT asset_id)` WHERE `asset_type='NEWS'` AND S AND `publisher IS NOT NULL AND trim(publisher) <> ''` | `publisher_present * 100 >= searchable_news * 95` |
| `dedup_identity_covered` | `COUNT(DISTINCT asset_id)` WHERE S AND `dedup_cluster_id IS NOT NULL` (all text-evidence asset types) | `dedup_identity_covered * 100 >= searchable_serving_evidence * 95` |
| `no_orphan_count` | `COUNT(*)` over (a) `canonical_asset_tickers.asset_id` not in `canonical_assets`, (b) `canonical_content_versions.asset_id` not in `canonical_assets`, (c) `canonical_subtype_assoc.asset_id` not in `canonical_assets`, (d) `canonical_subtype_assoc` rows whose `subtype_table`/`subtype_pk_value` do not resolve to the subtype table PK, (e) `canonical_subtype_assoc.canonical_content_version_id` is non-null and does not resolve **or the bound content version belongs to a different asset** (`JOIN canonical_content_versions v ON v.canonical_content_version_id = a.canonical_content_version_id AND v.asset_id != a.asset_id`; ownership equality, not only existence), (f) `canonical_structured_fact_refs` rows whose `(source_table, source_pk_json)` do not resolve, (g) `normalized_provenance` rows with non-null `canonical_asset_id` not in `canonical_assets`, (h) `normalized_provenance` rows with non-null `canonical_content_version_id` not in `canonical_content_versions` **or whose content version belongs to a different asset than `canonical_asset_id`** (when both are non-null) | `= 0` |
| `eligible_assets` | `COUNT(DISTINCT asset_id)` WHERE `eligible_at IS NOT NULL AND eligible_at <= cutoff_at` | reported |
| `material_capable_evidence` | `COUNT(DISTINCT asset_id)` WHERE `content_state='FULL_TEXT'` AND S | reported (FULL_TEXT only) |
| `EMPTY_FAILED_excluded` | `COUNT(DISTINCT asset_id)` WHERE `content_state IN ('EMPTY','FAILED')` AND S — must be 0 (integrity: such rows carry `serving_status='excluded'` by the mapping above) | `= 0` |
| `structured_fact_certified` | `COUNT(*)` FROM `canonical_structured_fact_refs` WHERE `certification_status='certified'` | reported |
| `structured_fact_excluded` | `COUNT(*)` FROM `canonical_structured_fact_refs` WHERE `certification_status IN ('excluded_missing_time','excluded_invalid')` | reported (never exposed to M4) |
| `structured_fact_ref_per_source_row` | per `(source_table, source_pk_json)`: exactly one ref (UNIQUE enforces; audit asserts) | `= 1` for every ref |
| `structured_fact_certified_plus_excluded_total` | per source table: `certified + excluded == COUNT(*)` of that source table | `= 0` shortfall |
| `structured_fact_populated_tables_certified` | every populated source table (`ohlcv`, `macro_observations`, `fundamental_statements`) has `COUNT(certified) >= 1` | M3 exit fails closed otherwise |

Ratio rules (exact):
- **Every ratio denominator must be > 0 or the audit fails closed** — a zero denominator is a FAILED gate, never a vacuous pass.
- **The same exact S predicate is used in the numerator and denominator of each ratio** — no denominator broadening or numerator narrowing.
- `aggregated_unknown` is a valid populated `source_class` (Frozen §5.1; `canonical/model.py:44`) and **counts as present** for the `source_class` gate when non-NULL/non-empty; it remains UNKNOWN/lead-only for evidence-role purposes (`source_role_for` → `SourceRole.UNKNOWN`, `canonical/model.py:79-81`) and is never material-capable for complex claims (Frozen §5.1 role ceiling).
- Only `NULL`/empty `source_class` counts as absent; only `NULL`/empty `publisher` counts as absent (unknown publisher is explicit NULL, never inferred — existing M3 plan).
- EMPTY/FAILED are never serving-eligible; `material_capable_evidence` is FULL_TEXT only.

- **M3-12B:** operator execution and report-only commit from the M3-12A HEAD. The report `git_revision` is the M3-12A SHA. No merge/tag.

**Pointers (exact):**
- served corpus relation / corpus_manifest: `corpus_manifest.is_current` + `corpus_served_chunks.manifest_id` (SQLite);
- lexical_index_state: `mode_served`, `corpus_manifest_id`, `lexical_generation_id`, `lexical_digest`, `row_count` (SQLite singleton row);
- active_generation.json: `data/lancedb_gold/<source_bundle_id>/active_generation.json` (filesystem; schema `active_generation_v1`);
- index manifest / source bundle IDs: `IndexManifest` (`retrieval/index_manifest.py`) + `active_generation.json` fields (`index_manifest_id`, `source_bundle_id`, `table_name`).

**Journal states (exact):** `PREPARED | SQLITE_COMMITTED | COMMITTED | ROLLING_BACK | ROLLED_BACK | FAILED`. Runtime admission is allowed only for `COMMITTED`, or for the prior generation after verified `ROLLED_BACK`. A journal state of `SQLITE_COMMITTED` alone (SQLite-new/dense-old) is **never** a successful or admissible state; runtime stays blocked and rollback is mandatory.

**Staged order under maintenance/quiescence (locked):**
1. Validate all inactive generations (M3-9 corpus candidate; M3-10 FTS + dense candidates): counts, digests, identity parity.
2. Preflight and source hashes (snapshot SHA, corpus manifest, canonical audit gates, DATA-01 report).
3. Write/fsync journal `PREPARED` (record `promotion_id`, `build_id`, `corpus_manifest_id`, `lexical_generation_id`, `lexical_digest`, `dense_index_manifest_id`, `active_generation_path`, `prior_*` pointer backups, timestamps, source hashes).
4. **Atomically flip corpus + FTS SQLite pointers in one `BEGIN IMMEDIATE` transaction** (`corpus_manifest.is_current` flip + `corpus_served_chunks.manifest_id` + `lexical_index_state` singleton row). One SQLite transaction, not two.
5. Write/fsync journal `SQLITE_COMMITTED`.
6. **Atomically replace the dense pointer** (tmp + `fsync` + `os.replace`, `retrieval/gpu_contract.py:_atomic_json` pattern).
7. Post-promotion verification: served chunk count == FTS row count == dense vector count; `DataRuntimeIdentity` emits actual loaded versions.
8. Write/fsync journal `COMMITTED`.

**Crash recovery / failure matrix (exact):**

| Failure point | Action |
|---|---|
| Crash before journal `PREPARED` | No pointers touched; rerun from step 1. |
| Crash after `PREPARED`, before SQLite flip | Journal says PREPARED; re-verify pointers unchanged, discard dense tmp if any, rerun. |
| Crash after SQLite flip, before `SQLITE_COMMITTED` | Journal is PREPARED but SQLite shows new pointers; roll forward by completing the flip record (`SQLITE_COMMITTED`), then run post-activation verification. |

**One rollback rule (any activation or post-activation verification failure):**
1. Block runtime (no admission).
2. Write/fsync journal `ROLLING_BACK`.
3. Restore the prior dense pointer.
4. Restore the prior corpus+FTS pointers in **one `BEGIN IMMEDIATE` transaction**.
5. Verify prior dense/FTS/corpus counts and identities.
6. Write/fsync journal `ROLLED_BACK`.

There is no alternative "operator repairs or rolls back" branch and no separate ordering: dense-first + SQLite-one-transaction is the only rollback path once any pointer has been touched. `FAILED` may describe a failure **before any pointer mutation** only; once pointers were touched, the terminal result must be `COMMITTED` or verified `ROLLED_BACK` — SQLite-new/dense-old is never a successful or admissible state.

**Durable promotion journal:** `data/manifests/m3_promotion_journal.json`, schema `m3_promotion_journal_v2` (adds `state` and `prior_*` fields), written with `fsync` (file + directory) before the first pointer flip and after each state transition.

**Idempotent rerun:** rerunning with the same `build_id`/manifest IDs re-verifies and is a no-op if already promoted (`COMMITTED`).

Raw archives, frozen snapshot, and previous generation remain immutable; prior generation retained through the rollback window.
