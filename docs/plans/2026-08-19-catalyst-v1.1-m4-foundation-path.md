`v1.1-m3-data`):

   `v1_result.RetrievalResultSet` does not carry `.final_results`, so a

   adapter.
3. `AgentRetrieverAdapter` consumes the legacy `RetrievalResult` via
   `_to_retrieved_evidence(result: RetrievalResult)`

4. The existing V1 conversion recreates incorrect runtime/temporal identity:
   `_to_v1_result_set` constructs a `DataRuntimeIdentity` from
   `requested_manifest_id` / `index_manifest_id` / mode / cutoff, and

   validated session/calendar identity.
5. The conversion hardcodes `provider="fixture"` and `ticker_scope=("AAPL",)`
   and does not preserve actual provider/publisher/ticker associations.
6. `_lookup_canonical_chunk` queries `corpus_build_chunks WHERE chunk_id = ?`
   — an unqualified chunk lookup that can resolve across generations — and
   returns `None` on zero matches, which silently falls back to the legacy
   shape instead of failing closed.
7. The conversion drops metadata that `EvidenceStateItem` requires:
   `section_key`, `chunk_ordinal`, `asset_type`, `content_hash`,
   `material_capability`, `serving_status`, `temporal_precision`,
   `independence_group_id`, `canonical_url`, and the evidence role.

#### 1.2 Locked decision: one production retrieval engine

- `ResearchExecutor` (M4-3) consumes only the V1.1
  `RetrievalResultSet` / `RetrievalHit` contract.
- Legacy `RetrievalResult` remains baseline-only for the sealed M1 path and
  the M1/M3 four-arm exit (`packages/eval/catalyst_eval/post_import/four_arm.py`
  passes `return_v1=False`); it is not a second production builder.
- `ProductionHybridRetriever.retrieve` returns the V1.1 set (or raises); it
  must never access `.final_results`.
- `ProductionHybridRetriever` must not recreate `DataRuntimeIdentity`. The
  actual `DataRuntimeIdentity` is injected from the runtime dependency
  authority (`RuntimeDependencyLoader` / `RuntimeDependencies`) and must match
  the requested corpus/index identities (`corpus_manifest_id ==
  requested_manifest_id`, plus the actual FTS/dense/embedding/reranker/query-
  policy versions emitted by the loaded components).
- The exact `TemporalIdentity` is supplied from the validated session/calendar
  path. Do not derive session open/start by copying the cutoff;
  `_temporal_identity_for_cutoff` is removed from the production path.
- Canonical metadata lookup binds `(requested corpus manifest/build,
  chunk_id)`: resolve the served chunks relation used by `retrieve_lexical`
  (`served_chunks_relation`) and query `manifest_id = ? AND chunk_id = ?` (or
  the repaired generation's `build_id = ? AND chunk_id = ?` resolved through
  the requested manifest). Fail closed on zero, duplicate, or conflicting
  matches (missing row; more than one row; or identity disagreement such as a
  `corpus_document_id` mismatch or a canonical asset/version join that does
  not resolve to exactly one consistent chain).
- Never query a chunk by unqualified `chunk_id` across generations.
- Remove hardcoded `provider="fixture"` and `ticker_scope=("AAPL",)`. Preserve
  actual provider, publisher, and ticker associations from the canonical row
  (`corpus_build_chunks.provider`, `ticker_associations`,
  `canonical_assets.publisher`).

#### 1.3 V1.1 RetrievalHit data-owned metadata contract

Extend the data-core `RetrievalHit`
(`packages/data-core/catalyst_data/retrieval/v1_result.py`) so every hit
exposes enough data-owned metadata for agents to construct `EvidenceState`

```text
- evidence_id
- canonical_asset_id
- content_version_id
- corpus_document_id
- chunk_id or fact_id
- section_key
- chunk_ordinal
- asset_type
- excerpt
- content_hash
- scores and ranks (per-stage; finite scores, positive contiguous ranks)
- source_class
- source role / evidence role
- content_state
- material_capability
- eligible_at
- temporal_precision
- serving_status
- ticker_scope
- provider
- publisher
- canonical_url
- dedup_cluster_id
- independence_group_id
- parse_quality
- retrieval_policy_version
- TemporalIdentity
- DataRuntimeIdentity
```

Derivation rules (locked):

- `evidence_role` = `source_role_for(source_class)` using the existing
  canonical mapping (`catalyst_data.canonical.model`); no invented semantic
  support.
- `material_capability` derives from `content_state`: `FULL_TEXT` →
  `MATERIAL_CAPABLE`; `TITLE_ONLY` → `LEAD_ONLY`; `METADATA_ONLY` →
  `NOT_CAPABLE`; `EMPTY` / `FAILED` are never retrieved.
- For `reported_news`, non-null `independence_group_id` means
  `independence_status = KNOWN_GROUP`, otherwise `UNKNOWN`. Unknown lineage
  must never be counted as independent.
- Scores stay finite; ranks stay positive and contiguous within each
  participating stage; missing modalities stay null.

### 5. Locked ContextPack draft/render/finalization order (amends M4-6)

Remove the current implicit circular build order. Lock this exact two-phase
design:

A. `ContextPackBuilder` creates an internal immutable `PackedContextDraft`
   containing deterministic inventory, role views, selected excerpts,
   truncation records, research history, observation, coverage, identities,
   and budgets. It does not fabricate the three final hashes.

B. `ContextPackFinalizer` receives:
   - `PackedContextDraft`;
   - exact prompt-template UTF-8 bytes/version;
   - deterministic text-message renderer;
   - registered `TokenCounter`.

C. Compute:
   - `prompt_template_sha256 = SHA-256(exact template UTF-8 bytes)`;
   - normalized rendered messages as an ordered tuple of strict text records
     `{role, content}`; reject unknown fields and non-text payloads in M4;
   - `rendered_messages_sha256 = SHA-256(canonical JSON of the ordered
     normalized messages)`;
   - `rendered_messages_tokens` using the selected labelled counter;
   - `TokenCountReport` and the final budget invariant.

D. Construct the final pack fields including prompt/render hashes and token
   report.

E. Compute:
   `context_pack_sha256 = SHA-256(canonical JSON of the complete final pack
   excluding only context_pack_sha256)`.

F. Instantiate the final `EvidenceAnalystContextPack` with that hash.

- The renderer must not include `context_pack_sha256` in the
  provider-visible messages, avoiding a hash cycle.
- Replay repeats the exact same pipeline and requires equality of template,
  rendered-message, and pack hashes.
- Use the repository's locked canonical JSON serialization (sorted keys,
  compact separators `(",", ":")`, UTF-8 — the `compute_state_hash` /
  `canonical_context_bytes` pattern). No `repr()`, no default Pydantic JSON,
  no character slicing, no `characters / 4` token estimate.
